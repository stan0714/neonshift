# tSKR 經濟模擬（PG-D-06，BRD 8.5）

`node tools/tokenomics/simulate.mjs [--users 100] [--days 30] [--seed 7]` → `docs/economics/sim.csv` 與摘要。參數與鏈上 Config／tournament_math 一致（基礎 10／5、Core 倍率 1.0～2.2、XP 100／50、門檻 0／450／1,500／3,600／7,500、每日上限 40；賽事質押 50、得獎 30%（A 10%）、未得獎退 50%、A／B 池 60／40、挹注上限 1,000）。

## 基準情境（100 人 × 30 天，seed 7）

| 指標 | 值 |
|---|---|
| 總產出 | 30,676 tSKR（每人每日 10.2） |
| 獎勵金庫 200,000 可支撐 | 約 196 天（100 人規模） |
| 30 天後等級分布 Lv1～5 | 4／18／51／27／0 |
| 錦標賽總質押 | 7,450，回流 7,443，國庫餘數 7 |
| **消耗／產出比** | **≈ 0.00**（目標 ≥ 0.6） |

使用者分群假設：活躍 30%（每日兩任務、賽事參與 70%）、一般 50%（步數 4 天／週、睡眠 2 天／週、參與 30%）、輕度 20%（每週 1～2 次、參與 5%）。

## 結論與待決（提請專案負責人，對應 BRD Q-03／8.5）

2026-09-14 定案「升級免費、無燒毀」後，原本主要的消耗項（升級成本 70% 燒毀／30% 入庫）已不存在；錦標賽在無沒收的情況下近乎零和（只剩整數餘數歸庫），因此 **消耗／產出比接近 0，無法達成 BRD 8.5 的 ≥ 0.6**。這不是實作缺陷，而是產品決策的結果；可選方案（任一皆需 BRD／SD 更新，不在現行估算內）：

1. 錦標賽獎金池抽成：`prize_a_bps + prize_b_bps < 10,000`（例如 60／30，剩 10% 歸庫），鏈上 `tournament_math` 已支援任意占比，只需在 `create_tournament` 參數化。
2. 未得獎退款比例下調（`loser_refund_bps` 50% → 30%），提高賽事淨流出；同樣只需參數化。
3. 新增自願性消耗：外觀（跑鞋配色）或藝廊展示位以 tSKR 兌換並燒毀。
4. 接受黑客松期間以「固定供給 + 金庫 runway」作為健康指標（200,000 tSKR 在 100 人規模可撐 ~6 個月），把 8.5 的比率目標改為 runway 目標。

在決策前，Pitch 以「固定供給、發放上限、金庫 runway」呈現經濟健康，不宣稱達成 0.6。
