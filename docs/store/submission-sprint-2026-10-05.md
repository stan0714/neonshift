## 2. 提交範圍與退出策略

**必保主線**：可獨立運行的 release APK → 清楚任務與紀錄 → 一條真實 Solana 錢包／交易／確認流程 → 收藏；評審無健康資料時能從 Profile 進唯讀預覽，預覽不能製造領取資格。

**爭取 SKR 獎**：在 10/1 結束前通過「真實資格→Devnet 訂單→錢包→確認→邊框→重開復原」，尤其不確定交易結果不可再次付款。若未通過，先修或在提交包停用付費入口並重剪影片、移除已完成 SKR 整合宣稱；不以危險付款換取多一項展示。主賽是否就緒仍依核心 gate 判斷。

**節日／活動完整報到／全套分享尺寸**：只放已驗收路徑。若需新鏈上升級或雙角色現場演示且 10/1 仍無證據，退到有標示的預覽或 roadmap；不能只在文件寫不展示，APK 卻留無法使用的 Mint／付款按鈕。主網、額外徽章美術、3D 鞋模、新社群功能、長影片不納入此衝刺。

## 5. 交付包與證據登錄

唯一最終版本清單使用 [clock-in-submission §9](clock-in-submission.md#9-最終交付登錄)，[judges-guide](judges-guide.md) 只同步對外入口，避免各處抄不同 SHA。建議新建當次 RC evidence 文件，不覆寫歷史測試結果。

- Release：標版本與已知限制；附件 APK 可直接下載；保留來源 tag/commit，不把 keystore、token、私鑰放入 repo。
- 實機：一段完整核心操作、錢包錯誤恢復、背景返回、一次分享；真實 Devnet Explorer 連結。尚無真實資格時，立即排實跑，不用假健康資料補。
- SKR：影片 D 段保留訂單、金額／網路、簽署內容、鏈上確認、外觀履約；清楚 `TEST SKR / Devnet / not official SKR`，依 [現行腳本](demo-video.md)。
- 影片：≤180 秒，以工具量測最終匯出檔；字幕和鏡頭不掩蓋測試網標籤；原型／預覽標識保留。
- Pitch：問題、手機體驗、真實交易、回訪理由、SKR、已實作／待驗收／roadmap、團隊入口。季節章若未通過只列 roadmap，不沿用過期文件稱全部未實作。
- 評審資料：測試活動／窗口在評審期間有效；測試 SOL／token 操作有替代路徑，後端維持可用，不只在錄影當天開機。評審期長度未核實前不安排過早關服務。
- 所有發布／部署與實際交易各自按既有授權流程執行；此規劃不是已執行或已核准付款的紀錄。
