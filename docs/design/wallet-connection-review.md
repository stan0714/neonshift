# 錢包連接體驗 Review

2026-09-21｜程式修正已完成；以下區分自動驗證與仍需真機重現的限制。

## 發現與修正

| 優先度 | 問題 | 處理 |
|---|---|---|
| 高 | 多次 connect 可同時開啟 MWA，回覆互相覆蓋 | Store 合併進行中的連接請求；已連接不再次打開錢包；clearError 不重設進行中狀態 |
| 高 | 啟動時 restore 較晚返回可能覆蓋新帳戶 | revision 檢查；舊 restore 不覆蓋新連接；disconnect 等連接結束後清理 |
| 高 | JSON 合法但地址損壞會使啟動失敗 | 驗證 token、地址與 URI 欄位，無效快取回到未連接，不開錢包 |
| 高 | 附加 App 登入失敗被吞掉，使用者無從理解後續為何又要登入 | 保存錢包連接，但顯示 App 登入尚未完成；由使用者按繼續後前往設定 |
| 中 | 所有階段只顯示「開啟錢包」 | 顯示開啟、核准、簽登入訊息、App 登入、保存五階段；失敗保留階段 |
| 中 | 錢包通訊問題被稱為 Devnet 故障 | 改為通訊中斷，不推定區塊鏈故障 |
| 中 | 未收到結果卻宣稱沒有簽章／沒有領取 | 移除未經證實的結論，提醒先查結果；未收到回覆不直接判定交易失敗 |
| 中 | SecureStore 寫入失敗與一般錢包錯誤混淆 | STORAGE_ERROR 專用文案，提示裝置保存步驟失敗 |
| 中 | 長時間只顯示 loading | 每階段等待 12 秒後顯示檢查錢包待核准請求與返回 App 的指引 |

## 還不能宣稱已排除的情境

- 外部錢包永久不回覆：此版未加入強制逾時／取消。不能只用 Promise.race 讓按鈕恢復，否則舊 MWA 仍可能在背景授權／登入並覆蓋下一次連線。後續需驗證 SDK 的原生 session 終止與清理，再加入安全取消。
- 斷開錢包仍會等待 deauthorize；外部錢包不回覆也可能等待。尚未實作強制中止與撤銷狀態回報。
- 附加登入失敗目前說明「App 登入尚未完成」，尚未在此頁細分 nonce／verify／伺服器錯誤；後續功能沿用既有登入及錯誤處理。
- 只有本機保存的授權不代表現在仍可簽署，實際簽署前繼續 reauthorize。
- 已辨識到一台 ADB 裝置，但本次沒有安裝新 build 或實際核准錢包請求，不能把自動測試當作真機連線驗收。

## 驗證與真機驗收門檻

WalletService、walletStore、onboarding、i18n 共 33 項測試通過（最後新增的 onboarding 案例另行重跑）；TypeScript 通過。包含重複點擊、restore 競態、损壞地址、登入失敗仍保留錢包、繼續設定、取消分類及既有重新授權／不重送簽章。i18n 測試仍有既有 act 警告。

真機需逐項驗收：首次授權、拒絕、返回鍵、手動切回 App、簽完不返回、飛航模式、登入 verify 失敗、關閉再開 App、撤銷 token、換帳戶、未安裝錢包、重複點擊及斷開重連。每例記錄裝置與錢包版本、停留階段和結果；不得保存 token、登入訊息或簽章內容至 review 紀錄。
