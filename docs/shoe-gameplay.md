# 跑鞋權限、維持挑戰與歷史收藏

> 2026-09-20 現況：App 睡眠已停用讀取與入口；下文睡眠／雙任務內容屬保留協議或舊規則，不代表目前 App 提供此功能。鏈上與後端仍保留，Lv5 維持門檻影響見 [停用盤點](./activity-sleep-review.md)。

v0.1｜2026-09-14｜依使用者新增方向制定；以下門檻為首版設計預設，尚未部署。

本版取代「只要累積 XP 就永久維持最高有效等級」的規則，保留免費升級、成就 NFT 不收 tSKR，以及已取得收藏不收回。優先於 BRD 17、SA 12、SD 12 與跑步藝廊專章中衝突的早期敘述。新規則上線需先完成玩家遷移及告知，不能回溯扣除既有資格。

## 1. 三個不同概念

| 狀態 | 意義 | 是否會下降 |
|---|---|---|
| 累積 XP／資格上限 | 代表長期累積；0／450／1,500／3,600／7,500 XP 對應 Lv1～5 上限 | 不因休息扣除；上限不等於目前有效等級 |
| Active level／目前裝備 | 目前可使用的鞋款、倍率與新增權限 | 維持挑戰未達標時下降，最低 Lv1 |
| Highest achieved／歷史最高 | 真正啟用過的最高鞋階；不是僅 XP 達標 | 永不因降級下降，作為收藏及回歸目標 |

免費 Core 與 Active level 同步，倍率仍為 1.0／1.2／1.5／1.8／2.2。歷史 NFT 的持有／購買／轉移不授予現行權限，也不改變原達成者。已持有高階鞋款降級後出現在「曾經達成」，目前裝備切換為有效階級。

## 2. 五階權限矩陣

權限是解鎖必要條件，不替代活動資格、PB 驗證、公開同意、庫存與唯一領取規則。高階包含低階權限。

| Active level | 鞋款 | 新解鎖能力 | 對應 NFT |
|---|---|---|---|
| Lv1 | Origin 原點 | 基本任務、跑步紀錄、查看 PB／藝廊、一般活動報名 | 已達成鞋階與基本里程碑 NFT；永遠可查看已取得收藏 |
| Lv2 | Pulse 脈動 | 新參加進階主題挑戰；獲取活動 NFT 資格 | 活動完賽 NFT；仍需主辦方確認完賽 |
| Lv3 | Phase 相位 | 獲取新 PB NFT 資格 | 最快固定距離／最遠單次，仍須符合 PB 驗證政策 |
| Lv4 | Surge 湧能 | 複合任務與進階收藏版式 | 成績同時符合指定複合挑戰才可取得專屬徽章；不把同一 PB 重鑄成相同作品 |
| Lv5 | Zenith 極境 | 高階維持賽季挑戰與限量外觀資格 | 完成一整期 Lv5 維持後取得該期「巔峰守護」成就，每期一枚 |

Lv4 複合挑戰是「同一有效跑步同時改善最快 5K 與最遠 PB」的設計示例；具體活動以版本化規則定義，未配置不可領取。Lv5 成就不要求每期跑得更快或更遠，只要求維持活躍。

**不可鎖住的功能**：錢包斷線、隱私／資料刪除、自己紀錄與收藏查看、已承諾退款、已獲得實體贈品的領取，不因降級失效。一般活動報名不強迫高階；主辦方選用高階限制時須事前標示。

## 3. 維持挑戰：階級越高，投入越規律

> **規則 v2（2026-09-20，DEC-04 方案 B 定案）**：第二每日任務由睡眠改為**運動 session**——App 內 GPS 記錄、同步後經伺服器審核通過（非待審）的跑步／健走，距離 ≥ 1 km 且移動 ≥ 10 分鐘，每 UTC 任務日一次；Health Connect 匯入與手動紀錄不計。維持點：步數 +100、運動 +100，一天最高 200；門檻表、活躍日、結算順序、XP 門檻不變。睡眠任務退役（鏈上 6045 拒收、歷史 receipt 保留）。只走路最高 Lv4；Lv5＝每天步數＋每週 2 次運動（或 6 天步數＋3 次運動，留一天休息）。模擬與候選比較見 [maintenance-v2.md](./economics/maintenance-v2.md)。下文 v1 敘述保留作歷史。

以成功的每日任務 ClaimReceipt 計分：步數 +100 維持點、睡眠 +50；一天最高 150。計分與 XP 數字相同，但**維持點每期重算，不是花費 XP**。同一天完成兩任務只算一個活躍日；交易失敗／重送不計。NFC 報到、購買 NFT、額外跑步里程、卡路里不增加維持點。

| 階級 | 累積 XP 上限門檻 | 每個 7 任務日週期維持點 | 至少活躍日 | 每天双任務的最低活躍日 |
|---|---|---|---|---|
| Lv1 | 0 | 不要求 | 0 | — |
| Lv2 | 450 | 200 | 2 | 2 |
| Lv3 | 1,500 | 450 | 3 | 3 |
| Lv4 | 3,600 | 700 | 5 | 5 |
| Lv5 | 7,500 | 900 | 6 | 6 |

必須同時符合點數與活躍日。Lv5 例：6 日各完成兩任務＝900 點，可保留一天休息；集中一天不能完成。單日步数遠超原任務門檻不給額外維持點；不設付費保級、補簽券或以高熱量／超長距離代替。

（v1）高階目前依賴睡眠來源可用性；因此睡眠資料實機可取得與誤判率是上線前置條件。若部分玩家無法取得合格睡眠，先重估全體一致的替代挑戰，不暗中放寬個別玩家／販售保級。→ v2 已以「運動 session」作為全體一致的替代挑戰。

## 4. 時間、升級、降級與回歸

### 4.1 統一結算規則

每個玩家以 `init_player` 的 UTC 任務日為 anchor，固定 7 日一期，區間 `[anchor+7k, anchor+7(k+1))`。結算使用鏈上 UTC，UI 同時顯示本地截止時間與 UTC 說明。不是每次打開 App 重新開始，也不因升級／降級／鑄造重設週期。

**每期結束執行一次**：先計算該期 points、active_days，再依下列順序：

1. 若目前 Lv≥2 且未達該階維持條件，降一階；本次結算不再同時升級。
2. 若通過維持（Lv1 永遠通過），在累積 XP 允許範圍內，升至該期維持成績能支撐的最高階。這也用於恢復曾經達到的高階，不再支付或重練 XP。
3. 升階更新 Highest achieved；其他情況保持歷史最高。切換倍率及可用權限，開始下一期。

XP 可在每日打卡後立即累積，但 Active level 只在固定期末切換；此規則取代原「每筆 XP 達標立刻同步升級」。因此原五階表的 3／10／24／50 日只代表 XP 最低累積天數，不再代表解鎖日。以每期全勤雙任務計算，首次啟用 Lv2／3／4／5 最早為第 7／14／28／56 任務日結算後。

每期最多降一階，沒有額外可反覆觸發的寬限重置。期內顯示「本期維持中」，截止前 48 小時與 24 小時可自願提醒；提醒文字不得要求忽略身體狀況完成任務。未達標只改遊戲權限，不扣代幣／XP、不罰款。

### 4.2 長時間離線

缺席多期，按所有已過期週期逐期結算，不能只降一階保留過期高權限。完全缺席四期的 Lv5 回到 Lv1。沒有交易時帳戶欄位可能未刷新，UI／API 需用相同規則顯示 effective level 與計算時間；任何受限交易執行前必須完成到目前期的結算。

降級不讓累積 XP 直接把玩家彈回高階。回歸需等當前完整週期結算並滿足目標階維持點／活躍日；允許恢復最高符合階級，不要求逐階再等四週。例：歷史 Lv5、目前 Lv3，該期 750 點／5 活躍日可恢復 Lv4，900 點／6 日才可恢復 Lv5。

### 4.3 系統事故與版本變更

平台故障造成無法領取的週期，以公開、可稽核的全域 incident freeze 暫停不利降級；凍結期不產生升階或 Lv5 維持成就。由管理治理決定受影響完整週期，截止前寫入並讓所有玩家一致讀取，不接受玩家自報裝置離線保級。若事後發現事故，需獨立補償流程，不能偷偷回寫已結算結果。

修改點數／權限時只能自新版本生效期起適用；不得追溯撤銷已獲資格。既有玩家遷移保留目前與歷史鞋階，從首次完整新週期開始挑戰。系統凍結與版本切換時點、管理權限須於鏈上實作前定案。

## 5. 鑄造資格與降級的關係

**預設採「達成時保留資格」**，避免玩家破 PB 後因等待主辦方核驗或錢包取消而失去成就。新增活動／PB 成就必須在達成的時間點具備最低 Active level；資格核准後，即使降級仍可領取該次作品。已獲資格不是將來無限使用高階權限。

- 鞋階 NFT：用 Highest achieved 判定，每階每錢包一次，降級後仍可補領歷史鞋階。
- 裝置 PB：achievement 達成時所屬週期的有效等級 ≥3；用當時等級歷史，不用匯入時的等級。回填舊運動無可查等級歷史時，只保留私人 PB，不自動授予 NFT。
- 活動 NFT／高階活動：報名時記錄承諾權限與規則，完成後保留該活動資格；中途降級不沒收已承諾活動權益，新的報名改查目前等級。
- 資格保留是穩定的 achievement ID／revision 與能力快照，不是永久有效簽章；實際簽章仍短效，重簽重新確認未領取／未撤銷。
- 上升回 Lv5 不重發鞋階 NFT；「巔峰守護」以 wallet＋season／epoch 唯一，可按期收藏，不能靠升降反覆刷同一期。
- 成績修正／作弊造成資格撤銷仍依 PB registry 流程，與正常降級完全分開。

NFT status 分成四個維度：所有權、達成紀錄、目前裝備、資格有效性。Historical 不等於 Revoked；灰階鎖頭只用於尚未解鎖／目前能力鎖定，不把已擁有 NFT 畫成被刪除。

## 6. 畫面與遊戲回饋

Gear 首屏：目前裝備 Lv、維持期倒數、`620 / 900 維持點`、`4 / 6 活躍日`、兩項下一步任務；下方為歷史最高及下一階能力。不用 XP 進度條混充維持條。

收藏頁分「目前裝備」「曾經達成」「尚未解鎖」；歷史鞋保留完整作品、首次達成日期與該期編號，外加 History 標籤及「恢復需完成本期…」說明。NFT 保持原作品，遊戲鞋 renderer 才使用 Active level。

降級訊息：「本期挑戰未完成，目前裝備為 Phase。你的 Zenith 成就仍在收藏中。」回歸訊息：「完成本期維持挑戰，Zenith 已重新啟用。」不以羞辱、損失資產或健康壓力文案催促。

藝廊榜單分 Active ranking 與 Lifetime achievements；前者依目前有效等級、累積 XP、錢包序排序，後者依歷史最高與收藏。標示資料結算時間，不把 stale profile shoe_level 當現行高權限。

## 7. 技術契約與遊戲防濫用（待實作）

新增 `active_level`、`highest_achieved_level`、`epoch_anchor`、`last_settled_epoch`、規則版本及每期摘要。既有 `shoe_level/core_level` 的對外語意須遷移為目前有效等級；不可只加 UI 降級而鏈上仍發舊倍率。

每個成功 claim 在同交易更新該期 `points`、7-bit `active_day_bitmap` 及 XP。週期摘要由鏈上固定計分，不接受後端自由指定點數；每日 bit 重複不增加活躍日。維持狀態与報到／熱量來源分離。

所有 clock_in、claim_achievement、活動新權限檢查先以鏈上時間 settlement；位於期末的 claim 先結算上一期，再把新任務計入新期。領獎金額用結算後的 Active level，該筆 XP 不立即觸發升級。既有 NFT 歷史領取用最高達成與 receipt，不用 NFT 現有持有量。

提供任何 payer 可呼叫的 `settle_player_epochs`；其權限僅推導規則，不能改參數。結算需 idempotent、單調 cursor 與 bounded batch，鏈上 consumer 發現尚未追上時回 `SettlementRequired`，App 補結算後再重建交易。最多批次上限與 rent 負擔待實作量測，禁止無界迴圈掃所有 ClaimReceipt。

每期有效等級、規則版本及結算摘要產事件並保存可追溯 history，用於延遲匯入的 PB。簽發者驗證 PB 發生時的權限後將 capability snapshot 綁進 eligibility registry／metadata commitment，不信任 client 自報歷史等級。事件索引未 finalized 或歷史缺失時 pending review，不自動授權。

初始化錢包／轉移 NFT 不重設維持週期；多錢包是不同玩家且不承諾防女巫。UI 預覽、測試案例與鏈上規則須用同版參數，但 production 只信任鏈上狀態。

## 8. 需求與交付順序

| 需求 | 內容 | 主要驗收 |
|---|---|---|
| FR-16.1 | 等級權限與歷史最高 | 目前／歷史分開，不能靠買 NFT 取得資格 |
| FR-16.2 | 7 日維持與降級 | 時間邊界、點數／活躍日双門檻、每期一次 |
| FR-16.3 | 回歸與歷史收藏 | 不扣 XP／NFT，不靠高 XP 自動回升 |
| FR-16.4 | 權限快照與鑄造 | 達成後降級仍可領；歷史回填不得用現在等級洗資格 |
| FR-16.5 | 規則版本／事故凍結 | 只向未來生效，遷移與全域凍結有可核對紀錄 |

先做參數模擬（至少 90 天：全勤、睡眠不可用、間歇、長休、回歸）→ 鏈上狀態／migration／結算 → 各交易與 PB registry 權限 → Gear／藝廊 → 實機與經濟驗收。不要先啟用前端降級而留舊合約。

邊界必測：期末前後、同日雙任務、反覆重送、Lv1 保底、四期缺席 Lv5→Lv1、恢復不重鑄、資格保留／作弊撤銷、資料晚到、NFT 轉移、期中政策變更、凍結、帳戶遷移、結算未完成時拒絕受限交易。

優化預留：權限 capability ID 與外觀 renderer 分離；未來新增挑戰類型與季節造型不改寫已領 receipt。點數、週期、階級門檻版本化；本期不做付費保級、隨機抽卡或強制資產銷毀。

## 9. 基礎首次紀念權限補充

[首次里程碑與紀念 NFT](./commemorative-nfts.md) 的首 5K／10K／半馬／全馬與 First Finish 歸 Lv1 基本里程碑，不要求當時 Lv2／3。活動專屬章仍沿用 Lv2 承諾，破 PB 仍需 Lv3，複合與巔峰仍用 Lv4／5。這項補充避免首次紀錄因鞋階不足消失，也不讓首次章取代高階 PB 權限。終身唯一性與來源驗證仍必須成立。

## 10. 探索冊與運動遊戲補充

[新增玩法](./sport-experience-gameplay.md) 提供週任務與帳號綁定外觀，走路／健走／跑步可參與。探索獎勵不增加既有 XP、維持點、活躍日或倍率；健康任務仍循既有 clock_in 規則，不能因同筆運動重複計獎。中斷探索不清空歷史、不提供付費補簽；來源失效與正常降階分開處理。新增任務不解決既有睡眠来源可用性的 DEC-04，該決策仍需獨立定案。
