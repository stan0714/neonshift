## 1. 現況與範圍

已查閱 App：`WorkoutsScreen` 有伺服器紀錄清單、Health Connect 匯入與本機待同步清單；`ActivityHistoryScreen` 是近 30 天打卡／收益歷史，不能當作完整運動日誌。`WorkoutRecorder.persistFinish` 目前保存後直接啟動背景同步；`LocalWorkoutStore.list` 目前由新到舊。本設計要求新增使用者開關及統一佇列，不能沿用清單順序直接補傳。

保留 Home／Gear／Arena／Profile 四 Tab。本期新增 Gear 外觀設定、Profile → 我的運動（Activity），Home 增加最近運動入口。Activity 參考運動日誌的月總覽、清單與詳情模式，採 NeonShift 自有版面。所有鞋階均可使用紀錄、同步與刪除。

## 2. 跑鞋與場景（FR-21.1）

Gear → 我的跑鞋，以卡片展示已取得鞋款、系列、款式、取得日期與「目前使用」。同時擁有多雙時點卡片預覽，再按「使用這雙」；只有一雙仍可設定背景。未取得款式顯示解鎖條件，不能直接套用；只有 XP 達門檻但尚未真正取得鞋款時不解鎖背景。新鞋取得先展示預覽與「立即使用／稍後」，不強制覆蓋原選擇。

外觀選擇 `selectedShoeId` 與 Active level 分開：前者只控制鞋面、背景及故事入口；後者仍依維持規則控制倍率與新成就資格。曾經合法取得的鞋款外觀可在正常降級後繼續使用，旁邊明示目前有效等級，不把高階造型當成高階能力。本段取代 shoe-gameplay 中「目前裝備」與有效等級混用的外觀敘述；不改維持點、XP、倍率或 NFT 資格。尚未發行的系列不能虛構為可選收藏；NFT 轉入不自動授予遊戲鞋款。

| 已取得鞋階／鞋款 | 場景提案 | 視覺語彙 |
|---|---|---|
| Lv1 Origin | 原點 | 原有深色背景、細網格 |
| Lv2 亞洲象 | 森林 | 深綠、低對比林冠剪影 |
| Lv3 玳瑁 | 海洋 | 深藍、稀疏水波與珊瑚輪廓 |
| Lv4 老虎 | 密林 | 琥珀細線、暗色林影 |
| Lv5 遠東豹 | 雪林 | 冷紫、雪林與星點 |

Gear 的「跟隨跑鞋背景」及 Profile → 外觀設定操作同一個 `shoeBackgroundEnabled`，首版預設開啟；關閉立即回到基本背景，保留所選鞋款。重啟保留選擇；新鞋取得、升階、換鞋不得偷偷開回。設定以本機玩家分區保存，登出回到訪客基本背景，換錢包不沿用另一人的收藏與偏好。重新安裝恢復預設並告知，跨裝置偏好同步另案。

路線底圖也跟隨跑鞋（2026-09-20 追加，PG-LINK-07）：摘要頁與活動卡縮圖的路線畫布預設用目前外觀等級的棲地當底圖（Lv.1 原點＝格線），可改選原有趣味圖層；曾取得的棲地才可明確選用，未取得顯示鎖定與解鎖等級。這是畫布內的圖，不受頁面背景開關影響。

背景用於 Home、Gear 與 Activity 的頁首／留白，內容卡片維持不透明深色底；運動記錄中、錢包確認與錯誤提示使用穩定基本底色。跟隨系統減少動態，首版以靜態紋理為主，文字對比與 48dp 操作區不受影響。資產載入失敗使用基本背景，不能卡住操作。切鞋更新未來 session 的鞋款快照，不回寫舊紀錄；回顧卡片可顯示「當時跑鞋」。未綁定玩家或無可靠取得紀錄的 session 標未指定，不推算歷史鞋款。

## 3. 連網自動同步（FR-21.2）

Profile → 資料與同步：「連上網自動同步運動紀錄」預設關閉，升級舊版同樣不默認同意。說明：開啟後，在可連線且已登入時上傳已保存的運動摘要；包含行動網路，原始 GPS 留在本機，不自動申領／簽署。可查看待傳筆數、最後成功時間、「立即同步」與錯誤原因。Health Connect 讀取權限、既有健康任務快取與這個上傳同意分開。

開關涵蓋所有運動摘要自動上傳入口：結束運動、重開 App、回前景、網路恢復、可用的系統背景排程及已授權匯入結果。關閉後先保存本機，不啟動新請求；已送出的單筆可能完成，UI 明示，完成後不再取下一筆。手動「立即同步」是一次授權，同樣走有序佇列，不永久打開自動同步；單筆重試不能跳過較早待傳紀錄。自動同步不彈錢包，不自動登入或擴大健康資料權限。Android 背景執行受系統限制，提示「系統允許時同步；開啟 App 可繼續」，不承諾連網即刻背景完成。

### 3.1 必須按運動時間由舊到新

1. 將完成且已落地的 session 放入持久化 outbox，綁定建立時的玩家／錢包。未登入先留本機，首次歸屬須確認；不得把 A 的紀錄傳給 B。
2. 每次取件以 `startedAtUtc ASC, endedAtUtc ASC, canonicalSessionId ASC` 穩定排序，使用 UTC 時點，不用顯示字串、建立檔案時間或上傳時間。同 session revision 依遞增序處理，未送出的旧 revision 可被最新 revision 合併取代。
3. 同一玩家僅一個 worker／一筆在途，手動、結束運動及重連共用鎖；等後端 ACK 且本機提交成功後才取下一筆。多裝置上傳由伺服器按玩家序列化套用，跨裝置晚到資料依下節重算，不假定手機鎖可以鎖住其他裝置。
4. 暫時失敗、逾時、401／403 暫停在隊首；網路錯誤採有上限退避，登入／權限問題需本人處理。顯示「較早紀錄待處理，後續暫停」，不能靜默跳過。永久無效項可由使用者明確排除，保留原因與待審狀態；排除不得增加統計／成就。
5. 幂等鍵為 `(owner, canonicalSessionId, revision)`，內容雜湊不符回衝突；逾時後查原結果或用同鍵重試。來源鍵及跨來源重複疑慮沿用 activity-running-gallery，不靠相近時間就刪掉真實運動。
6. 09/17、09/18、09/19 三筆離線紀錄即使倒序出现在 UI，也必須 17 → 18 → 19 上傳。同步清單顯示相同順序與目前處理項，頁面排序不改動佇列。

### 3.2 晚到、更正與刪除

新發現更早紀錄時，在目前在途項完成後重新排序剩餘佇列。已經傳完的紀錄不假裝能倒轉網路順序；伺服器把晚到紀錄插回運動時間線，自最早受影響時間重算 PB、首次里程碑與統計，套用達成當時有效等級及品質規則。查不到資格歷史則待審。已鑄 NFT 依既有 corrected／invalidated 規則處理，不能重複鑄造或以目前鞋階補資格。

source revision、更改開始時間與刪除均觸發重算。刪除先寫 tombstone 阻止重匯入，與在途 ACK 協調後提交伺服器刪除，保留「刪除待同步」直到確認；刪除請求不被一般上傳復活。未同步紀錄刪除一併移除 outbox 與本機路線。伺服器 session 與摘要保留仍遵守既有 30 天政策；長期雲端歷史需另行同意及政策，不默默擴大保留。

## 4. 我的運動 Activity（FR-21.3）

```text
我的運動                         資料與同步
2026 年 9 月 〈  〉               [月曆／清單]
本月 8 次 · 32.4 km · 3 小時 12 分鐘
[全部] [跑步] [健走] [散步]       日期／來源／狀態
待同步 3 筆 · 自動同步已關閉      [立即同步]
09/17 07:10  跑步   5.00 km   30:00   6:00/km
  亞洲象 · 裝置紀錄 · 僅本機       [查看詳情]
09/18 18:00  健走   2.40 km   28:00   5.1 km/h
  原點 · 已同步                    [查看詳情]
```

首版預設運動開始時間由舊到新，可選由新到舊並記住瀏覽偏好；同步永遠由舊到新。月分組／月曆依該 session 保存的當地時區顯示，跨午夜歸開始日，詳情保留時區；改手機時區不改事件順序。月份選擇、運動類型、資料來源及同步狀態可組合篩選；分頁使用開始時間＋穩定 ID 游標，載入期間固定查詢快照，刷新才合併新結果，避免重複／漏列。

列表合併本機與伺服器，按 canonical ID 去重，已同步同一筆只能顯示一列；未同步、已同步、待審、同步失敗、刪除待同步明確分開。待審可在私人日誌顯示，但總覽只計有效且去重的紀錄，旁列排除筆數；不將同步成功當作成績認證。距離／時間缺值顯示 —，不當 0。跑步顯示平均配速，健走／散步顯示平均速度，另見 intent 與 sport 定義。

詳情：開始／結束時間、運動類型、距離、經過／移動時間、配速或速度、步數、活動熱量、公里分段／圈數、來源／品質、當時鞋款、PB／首次章狀態與同步狀態。缺資料隱藏相應圖表並說明；不以均速偽造最快分段。本機路線僅在有原始點且已完成地圖整合時呈現，伺服器摘要不可捏造路線。歷史詳情沿用同一頁，支援本機 ID 與遠端 ID 對應。

空白狀態引導開始運動或授權匯入；離線仍能看本機已保存紀錄；未登入仍可看訪客本機資料，無權查看其他錢包。登入失效不清掉本機日誌。打卡收益保留獨立「打卡紀錄」入口。超過伺服器保留期可繼續看本機存在的紀錄；明示卸載或換裝置可能無法恢復，不把雲端摘要稱為永久備份。

## 5. 資料與介面契約（待實作）

- `AppearancePrefs(owner, selectedShoeId, shoeBackgroundEnabled)`；`OwnedShoe(id, owner, seriesId, level, variant, acquiredAt, entitlementSource)`。取得紀錄為權威，現有固定分配演算法不得重抽。
- `SyncPrefs(owner, autoSyncWorkouts=false)`；`WorkoutOutbox(owner, canonicalSessionId, revision, startedAtUtc, endedAtUtc, payloadHash, status, attempt, nextAttemptAt, lastError)`；status：queued／sending／retry_wait／blocked／acked／excluded。崩潰遺留 sending 先核對同鍵結果再恢復。
- Session 新增 `owner`、`recordedTimeZone`、`shoeSnapshot`、`revision`、`deletedAt`；既有資料缺鞋款／時區標未知，不推測個人過去狀態。
- 擴充既有 `/v1/me/workouts`：`from,to,sport,intent,source,status,order,cursor,limit`；日期邊界 `[from,to)`，回傳 `nextCursor`、查詢快照及涵蓋範圍。摘要／詳情只限本人；詳情需 canonical ID 映射，回傳來源、分段、鞋款與同步版本。
- 既有匯入端點增加幂等與 revision 契約；ACK 回 session ID、accepted revision、重算狀態。同步「已保存」和成就「重算中／已確認」分開，後端先 commit 再 ACK。刪除端點檢查 owner 並返回 tombstone revision；未知或無權 ID 不洩露他人資料。

## 2026-09-20 路線外觀固定與跑鞋連動

運動前選擇路線背景，開始時保存具體圖層／版本；摘要與 Activity 只讀每筆快照，儲存後不可更改。舊紀錄固定基本格線。此規則取代舊版摘要頁底圖編輯與歷史跟隨目前偏好的敘述。已完成範圍及延伸評估見 [專章](design/shoe-route-linkage.md)。
